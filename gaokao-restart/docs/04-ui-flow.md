# 任务 04：标准版 UI 与交互

## 1. 目标

实现独立项目的完整可玩 UI：天赋选择、属性分配、轨迹推进、总结重开。

## 2. 写入范围

允许写入：

- `gaokao-restart/src/ui/**`
- `gaokao-restart/src/main.ts`
- `gaokao-restart/src/app/**`
- `gaokao-restart/src/ui/styles/**`

## 3. 页面流程

### 首页

- 标题：《高考重开模拟器》。
- 显示累计重开次数。
- 主按钮：开始重开。

### 天赋页

- 展示 10 个候选天赋。
- 选择 3 个。
- 互斥时提示冲突。
- 显示稀有度和标签。

### 属性页

分配 20 点：

- 学力 `INT`
- 精力 `STR`
- 资源 `MNY`
- 心态 `SPR`

需要显示剩余点数。剩余点数不为 0 时不能开始。

### 轨迹页

- 显示年龄、阶段和当前回合，例如 `17 岁 · 第 3 回合 · 百日冲刺`。
- 显示当前属性：学力、精力、资源、心态、志愿、风险。
- 显示分数潜力 `SCR/HSCR`。
- 支持下一回合。
- 支持自动跑完。
- 展示事件日志。

### 总结页

- 显示结局档位和名称。
- 显示结局描述。
- 显示高考分数、志愿情报、风险、总评。
- 展示本局天赋。
- 选择一个可继承天赋。
- 再来一局。

## 4. 交互要求

- 手机端可单手操作。
- 按钮文字不能溢出。
- 日志可滚动。
- 自动跑完时不要卡死 UI。
- 结局出现后禁用“下一回合”。

## 5. 视觉要求

首版以清晰和稳定为主：

- 白底或浅色纸张感。
- 重点色不超过两种。
- 卡片圆角不超过 8px。
- 不做大段玩法说明文案。
- 不做营销式 landing page。

## 6. 验收

- 玩家从首页到总结能完整跑一局。
- 高考属性名不出现原作的“颜值/快乐/寿命”等误导文案。
- 桌面和移动宽度均无明显重叠。
- `pnpm build` 通过。
