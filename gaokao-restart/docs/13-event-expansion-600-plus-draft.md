## 3. 效果口径

效果草案用简写表示，最终落 JSON 时再统一调数值。

- `正`：整体收益为正，例如 `+SPR +VOL`、`+SCOREMOD`、`RSK-`
- `负`：整体收益为负，例如 `SPR- RSK+`、`SCOREMOD-`
- `混`：有收益也有代价，例如 `+VOL RSK+`、`+SCOREMOD SPR-`
- 建议最终比例：纯正面约 35%-40%，纯负面约 20%-25%，混合约 35%-40%。

## 5. 接入建议

1. 先做文案审核，删掉不喜欢的主题和过于相似的句式。
2. 再把候选事件转为 JSON，字段建议保持：
   - `id`
   - `stage`
   - `phase`
   - `text`
   - `effect`
   - `grade`
   - `weight`
   - `flag`
   - `tags`
3. 不建议一次把 300 条全塞入现有回合池同权重。应按阶段拆包，每个回合新增 6-12 条，避免稀释关键事件。
4. 生活/休闲事件建议多数做成 `SPR/STR/VOL/RSK` 变化，不要大量加 `INT/STR`，避免再次推高属性触顶率。
5. 高三和出分期事件可以提高 `VOL/RSK/SCOREMOD` 权重，因为这些阶段本来就应该更影响分数和录取稳定性。

## 6. 审核重点

- 是否有不希望出现的生活主题。
- 是否需要增加更多乡镇/县中/寄宿/走读差异。
- 是否需要为物理组/历史组单独拆一些事件。
- 是否需要把恋爱、追星、游戏、家庭冲突这类事件控制得更轻一些。
- 是否需要为新增事件配套新增结局或成就。
