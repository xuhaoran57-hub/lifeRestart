# 人生重开模拟器设计文档

## 1. 项目概述

### 1.1 项目定位

《人生重开模拟器》是一款单人网页模拟游戏。玩家通过选择天赋、分配初始属性并推动角色逐年成长，观察角色在随机事件和天赋影响下的人生轨迹，最终获得总结评价、成就进度和可继承内容。

### 1.2 核心体验

- 用少量开局决策撬动一整局人生变化。
- 在随机事件与条件分支中体验高复玩价值。
- 通过多周目逐步解锁更多成就、收集更多事件和天赋。
- 在“重开”中追求更高总评、更长寿命或特殊人生结局。

### 1.3 目标玩家

- 喜欢数值模拟、文字冒险、随机叙事的玩家。
- 喜欢短局循环和重复挑战的轻度玩家。
- 喜欢研究天赋组合、事件条件与隐藏内容的探索型玩家。

## 2. 游戏整体流程

### 2.1 主流程

1. 进入主菜单。
2. 选择开始重开。
3. 进入模式选择。
4. 选择普通模式或名人模式。
5. 普通模式下先抽取并选择天赋，再分配初始属性。
6. 名人模式下直接从预设角色中选择一位开始人生。
7. 进入人生轨迹阶段，按年龄逐年推进。
8. 生命值归零后进入人生总结。
9. 选择一个天赋继承到下一局。
10. 增加重开次数并返回主菜单。

### 2.2 页面结构

- 主菜单：开始重开、成就、感谢名单、主题、存档。
- 模式选择：普通模式、名人模式。
- 天赋选择页：抽卡并选择 3 个天赋。
- 属性分配页：分配颜值、智力、体质、家境。
- 人生轨迹页：逐年展示人生事件与属性变化。
- 总结页：展示人生评分、最终结果和可继承天赋。
- 成就页：展示累计进度与已解锁成就。
- 感谢页：展示支持者名单。
- 弹窗：消息提示、成就解锁提示、主题切换、存档导入导出。

## 3. 核心玩法循环

### 3.1 开局阶段

每局开始时，系统会根据当前周目状态生成候选天赋列表。玩家必须从中选择 3 个天赋。部分天赋之间存在互斥关系，无法同时选择。部分天赋还会为后续属性分配提供额外点数。

在普通模式中，玩家完成天赋选择后进入属性分配阶段。系统提供固定基础属性点，玩家将其分配到：

- 颜值 CHR
- 智力 INT
- 体质 STR
- 家境 MNY

快乐 SPR 不参与手动分配，使用默认初始值。

### 3.2 人生推进阶段

游戏以“年龄”为时间轴逐年推进。每推进一年，会按以下顺序执行：

1. 年龄加 1。
2. 读取该年龄配置的年龄天赋触发列表。
3. 触发满足条件的天赋效果。
4. 从该年龄对应事件池中筛选可触发事件。
5. 按权重随机抽取一个事件。
6. 结算事件效果。
7. 若事件带有分支，则继续进入下一个事件。
8. 更新当前属性、最高属性、最低属性和历史记录。
9. 判断生命值是否小于 1，若是则结束本局。

### 3.3 结算阶段

角色死亡后进入总结页面。系统会基于本局过程中的最高属性、年龄和综合得分给出评价。随后玩家可以从本局已拥有天赋中选择 1 个继承到下一局，形成多周目成长闭环。

## 4. 核心系统设计

### 4.1 属性系统

#### 4.1.1 当前属性

局内的主要属性包括：

- AGE：年龄
- CHR：颜值
- INT：智力
- STR：体质
- MNY：家境
- SPR：快乐
- LIF：生命

#### 4.1.2 派生属性

系统会自动记录一局中的极值：

- HAGE / LAGE：最高年龄 / 最低年龄
- HCHR / LCHR：最高颜值 / 最低颜值
- HINT / LINT：最高智力 / 最低智力
- HSTR / LSTR：最高体质 / 最低体质
- HMNY / LMNY：最高家境 / 最低家境
- HSPR / LSPR：最高快乐 / 最低快乐

这些值用于人生总结和成就判定。

#### 4.1.3 总评规则

总评 SUM 由以下规则计算：

- 将最高颜值、最高智力、最高体质、最高家境、最高快乐相加。
- 上述结果乘以 2。
- 再加上最高年龄的一半。
- 最终向下取整。

该规则让人生质量与寿命同时参与结算，但属性成长仍然是主导因素。

### 4.2 天赋系统

#### 4.2.1 天赋组成

每个天赋由以下信息组成：

- ID
- 名称
- 描述
- 稀有度
- 触发条件
- 属性效果
- 是否专属
- 是否互斥
- 替换规则
- 初始属性点加成

#### 4.2.2 天赋抽取

每局默认抽取 10 个候选天赋供玩家选择。天赋按稀有度概率生成，不同稀有度出现概率不同。

周目进度会影响抽卡权重：

- 重开次数越高，稀有天赋出现概率会提升。
- 已获得成就越多，稀有天赋出现概率也会提升。

这意味着多周目游玩本身会逐步改善开局质量。

#### 4.2.3 天赋互斥

某些天赋具有显式互斥关系，例如性别相关天赋。玩家选中一个后，若与已选天赋冲突，则系统拒绝选择并提示冲突信息。

#### 4.2.4 天赋替换

部分天赋在正式开局时不会直接保留，而是被替换为另一批候选天赋中的一个。替换规则支持：

- 按目标稀有度替换
- 按指定目标天赋替换
- 连锁替换

这为开局带来了额外的不确定性和惊喜感。

#### 4.2.5 天赋触发

天赋在局内根据条件自动触发。大多数天赋默认只能触发一次，只有部分年龄条件类天赋可以在多个指定年龄重复触发。

### 4.3 事件系统

#### 4.3.1 事件组成

每个事件可包含以下内容：

- 事件文本
- 稀有度
- 追加文本
- 属性影响
- 生命影响
- 年龄影响
- 是否允许随机出现
- 包含条件
- 排除条件
- 分支条件

#### 4.3.2 事件筛选逻辑

每一年不会直接从整个事件库随机，而是先从该年龄绑定的事件池中筛选：

- 被标记为 `NoRandom` 的事件不会进入普通随机池。
- 若事件存在 `exclude` 且当前条件满足，则该事件不可触发。
- 若事件存在 `include`，则只有满足条件时才可触发。

通过这些规则，事件可以被设计成隐藏链、专属事件或后续剧情。

#### 4.3.3 事件分支

事件可以带有条件分支：

- 如果分支条件满足，则跳转到指定下一事件。
- 若没有命中分支，则只结算当前事件。

因此系统支持多段式人生片段，例如死亡后复活、前置行为引发的后续剧情等。

### 4.4 年龄系统

年龄表负责定义每个年龄可能出现的内容：

- 当前年龄会绑定一个事件池。
- 当前年龄也可以绑定需要在该年龄尝试触发的天赋。

事件池中的每条数据可以带权重，例如 `10001*110` 表示事件 `10001` 在该年龄出现的权重为 `110`。这使策划可以精细控制不同年龄段的事件分布和人生节奏。

### 4.5 成就系统

#### 4.5.1 成就触发时机

成就根据不同时机判定：

- START：开始人生后判定
- TRAJECTORY：人生推进过程中逐年判定
- SUMMARY：人生总结时判定
- END：点击重开并完成结算时判定

#### 4.5.2 成就作用

成就系统承担两种功能：

- 作为长期收集目标提升复玩动力
- 作为元进度的一部分，影响稀有天赋抽取概率

### 4.6 名人模式

名人模式跳过普通的“抽天赋 + 分配属性”流程，直接提供若干预设角色供玩家选择。每个角色自带：

- 初始属性
- 预设天赋组

该模式的作用：

- 提供更具主题性的开局体验
- 让玩家快速体验特定成长路线
- 降低普通模式的决策门槛

此外，系统还内置一个隐藏“独特角色”生成逻辑，满足特定条件后可以生成特殊角色并写入本地存档。

## 5. 数值与规则配置

### 5.1 默认配置

- 初始可分配属性点：20
- 天赋选择数量：3
- 天赋候选数量：10
- 单项属性分配范围：0 到 10
- 默认初始快乐：5

### 5.2 稀有度体系

系统存在多档稀有度，天赋、事件、总结评价和成就都共用等级概念。不同主题会用不同颜色表现稀有度，但逻辑一致。

### 5.3 属性评价规则

总结页和成就页会根据配置表对以下指标进行分档评价：

- 最高年龄
- 最高颜值
- 最高智力
- 最高体质
- 最高家境
- 最高快乐
- 总评
- 重开次数
- 成就数量
- 天赋收集率
- 事件收集率

这让数值不仅参与结算，也参与可视化反馈和长期目标展示。

## 6. 数据驱动设计

### 6.1 数据来源

游戏主要内容由 Excel 表驱动，核心配置包括：

- `data/zh-cn/talents.xlsx`
- `data/zh-cn/events.xlsx`
- `data/zh-cn/age.xlsx`
- `data/zh-cn/achievement.xlsx`
- `data/zh-cn/character.xlsx`

同时提供英文版本对应表，用于多语言切换。

### 6.2 数据转换流程

项目通过脚本将 Excel 内容转为前端运行时使用的 JSON：

- 开发阶段编辑 `.xlsx`
- 执行 `pnpm xlsx2json`
- 转换后的 JSON 输出到 `public/data`
- 游戏运行时按语言加载对应 JSON 数据

这种设计保证了策划内容与程序逻辑的分离，便于非程序人员参与内容迭代。

### 6.3 条件表达式系统

策划表中的条件支持：

- 括号
- 与 `&`
- 或 `|`
- 比较运算 `> < >= <= = !=`
- 集合判断 `? !`

例如：

- `TMS>9`
- `AGE?[1,2,3]`
- `(AGE![500])&(TLT?[1148])`

这使事件、天赋、成就都能在不改代码的情况下编写复杂触发条件。

## 7. 界面与交互设计

### 7.1 主菜单

主菜单承担游戏总入口作用，并根据重开次数决定是否显示部分功能入口。玩家尚未完成一局时，成就和感谢等入口会被隐藏，形成轻量的新手体验。

### 7.2 天赋选择页

- 首先点击“抽卡”显示候选天赋。
- 天赋按稀有度展示不同视觉样式。
- 已选天赋会高亮。
- 当已选数量不足 3 个时，不允许进入下一步。
- 若发生互斥，会弹出提示信息。

### 7.3 属性分配页

- 支持加减按钮调整属性。
- 支持直接输入数值。
- 支持一键随机分配。
- 若还有剩余点数，不允许进入下一阶段。

### 7.4 人生轨迹页

- 以时间轴或列表形式逐年展示人生文本。
- 支持点击或自动播放推进。
- 支持速度调节。
- 同步显示当前核心属性。
- 当年龄达到 100 岁以上时，额外显示强化特效。

### 7.5 总结页

- 展示本局关键属性评价。
- 展示总评和寿命。
- 展示本局天赋列表。
- 允许选择继承天赋。
- 点击再次开始后回到主菜单。

### 7.6 成就页

- 展示累计重开次数、成就数、事件收集率、天赋收集率。
- 成就按是否解锁、是否隐藏、稀有度进行展示。
- 未解锁隐藏成就只显示 `???`。

### 7.7 存档系统

支持以下操作：

- 复制当前本地存档文本
- 从剪贴板读取存档文本
- 导出为本地 JSON 文件
- 从本地 JSON 文件导入
- 打开文本备份面板进行人工编辑和恢复

存档内容本质上是 `localStorage` 的序列化结果，因此覆盖导入后会立即改变主题、进度和继承状态。

### 7.8 主题系统

项目内置多套视觉主题：

- default
- dark
- light
- cyber

主题系统只切换表现层，不改变玩法逻辑。不同主题复用同一套核心流程，但页面布局、控件样式、特效和颜色体系不同。

## 8. 技术架构设计

### 8.1 分层结构

项目可分为三层：

- 核心玩法层 `src/modules`
- 工具与条件层 `src/functions`
- 界面与主题层 `src/ui`

#### 核心玩法层

包含以下模块：

- `life.js`：总控模块，串联属性、天赋、事件、成就、角色系统
- `property.js`：属性与局内状态管理
- `talent.js`：天赋抽取、互斥、替换与触发
- `event.js`：事件筛选与执行
- `achievement.js`：成就判定与触发
- `character.js`：名人角色与特殊角色逻辑

#### 工具层

- `condition.js`：条件解析与判断
- `util.js`：深拷贝、加权随机、格式化等基础能力

#### 表现层

- `uiManager.js`：页面切换、弹窗、资源加载、主题注入
- `views.js`：页面映射和主题配置中心
- `themes/*`：不同主题下的页面实现

### 8.2 事件通信

项目使用简单的全局事件总线：

- `$$event`
- `$$on`
- `$$off`

主要用于：

- 成就解锁弹窗
- 消息提示弹窗

这种方式降低了 UI 与逻辑层之间的直接耦合。

### 8.3 本地持久化

元进度通过 `localStorage` 保存，主要包括：

- 重开次数
- 已拥有天赋
- 已见事件
- 已解锁成就
- 当前主题
- 继承天赋
- 隐藏角色数据

这套持久化设计支撑了游戏的多周目体验。

## 9. 设计亮点总结

### 9.1 高复玩性

游戏通过“短开局决策 + 大量随机事件 + 持久化元进度”形成天然高复玩结构，适合反复体验。

### 9.2 数据驱动内容扩展

策划可主要通过配置表新增：

- 天赋
- 事件
- 年龄阶段内容
- 成就
- 名人角色

不需要大量修改核心代码，扩展成本较低。

### 9.3 轻量但完整的成长闭环

虽然单局很短，但通过以下机制形成了完整长期循环：

- 重开次数增长
- 收集率提升
- 成就解锁
- 稀有天赋概率提升
- 继承天赋优化下一局开局

### 9.4 同逻辑多主题复用

项目的 UI 和玩法耦合较低，因此同一套规则可以快速适配多种皮肤和视觉方案，适合后续继续增加主题版本。

## 10. 后续扩展建议

### 10.1 内容扩展方向

- 新增更多天赋替换链和成长派系。
- 增加更强的年龄段主题事件包。
- 增加职业、关系、地区等中间层系统。
- 扩充隐藏成就和特殊结局。

### 10.2 系统扩展方向

- 增加局内关键选择节点，而不是完全自动推进。
- 增加事件图鉴和结局图鉴。
- 增加职业线、情感线、家庭线等长期状态变量。
- 增加种子系统，支持复现特定人生。

### 10.3 产品化方向

- 接入排行榜或分享码系统。
- 增加每日挑战、限定人物或主题活动。
- 增加移动端更强的触控交互和分享链路。

## 11. 结论

《人生重开模拟器》采用了典型的“高随机短局模拟 + 多周目积累”设计框架，用简洁的规则构建出极强的可传播性与复玩性。其成功关键不在复杂战斗或深系统叠加，而在于：

- 开局决策足够轻
- 过程反馈足够密集
- 随机结果足够戏剧化
- 长期成长足够明确

从实现角度看，项目结构清晰、内容强数据驱动、主题层与核心层分离明显，非常适合持续追加内容、视觉主题或衍生模式。
